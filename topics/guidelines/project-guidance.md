# 项目开发规范

指导代码实现与项目文档维护, 保持职责清晰和语义完整.

## Code

- 设计: 从实际场景与已确认前提出发. 先职责与数据流, 后模块与函数.
- 职责: 同类逻辑集中, 状态归属明确. 接口只传必要信息.
- 抽象: 复用已有能力. 函数拆分应有明确职责或复用需求.
- 精简: 合并重复逻辑与状态. 删除无独立职责的转发和中间层. 保留必要语义与约束.
- 约束: 检查, 回退与兼容以实际需求为依据.
- 注释: 说明职责, 接口与必要假设. 算法与边界就近解释.
- 修改: 围绕当前任务.
- 验证: 具体输入 → 预期行为 → 实际结果. 优先复用现有验证方式.

## Document

- README: 项目用途, 必要前提, 快速开始与文档入口.
- 架构设计: 模块职责, 依赖关系, 数据流与关键取舍.
- 接口说明: 输入输出, 使用条件, 行为约定与错误处理.
- 文档组织: 按需拆分. 详细说明集中维护, 相关位置用链接衔接.
- 更新: 实现变化时同步相关说明. 保持命令, 路径与示例有效.
